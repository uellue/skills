# skills

Marketplace of one plugin, `plugins/kaizen/`: skills in `skills/*/SKILL.md`, templates and briefs in `references/`, scripts in `scripts/`. What the plugin must do and for whom: `design/` (stakeholders, requirements, examples with IDs, testing plan, the kaizen ledger with its open rows); finished records and closed ledger sections in `design/archive/`, read only for history. Rerunnable checks of the skills' behaviour: `benchmarks/`. Hallway-testing the plugin means `/plugin-selftest <scenario>` (`benchmarks/plugin-newcomer/`): the subject is the plugin, never the scenario's project; `notes-tags/` compares processes.

- Terms: `GLOSSARY.md` sets the words used here and in what the skills and the README say to their users; use its terms and not the ones it lists under _Avoid_, and when a term is resolved or a new one appears, propose the glossary change in the same piece of work.
- Pre-commit check: `./check.sh` (unit tests of the scripts and hooks on synthetic data, lint of the skill texts, references and manifests, the report of uncovered examples; the pre-commit hook and CI run the same). Say "ready" only with its output; a change to a script gets a test in `tests/`.
- Try your edits: the marketplace is this checkout and lists the plugin by a relative path, so it loads in place; `/reload-plugins` (or a new session) picks up changed skills, no version bump needed (code.claude.com/docs/en/plugins/loading.md, checked 2026-11-05). After editing a skill, run `python3 plugins/kaizen/scripts/version.py --stamp`: each skill carries a text id that tells a session it runs an older text, and the check fails while one is stale.
- Claims about Claude Code's behaviour (plugin and skill format, transcript layout, skill visibility, hooks, `claude plugin eval`) are checked with the `claude-code-guide` agent or the CLI's `--help` before they go into a skill, and the source is named.
- A change beyond a few hundred lines gets a review by an agent that did not write it, briefed with the diff, `design/requirements.md` and `CODING_STANDARDS.md`, before it is called ready, with the brief kept in `CODING_STANDARDS.md`.
- This repository is public: no details of other projects, no security findings, no transcripts. Private material goes to `.claude/debriefs/` (ignored).
