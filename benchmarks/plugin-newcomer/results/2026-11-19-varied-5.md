## What this combination found that the fixed scenarios could not

An existing `CLAUDE.md` with the user's own rules, plus deploy-on-push, plus an unanswered issue, plus "What should I do first?". The scenarios so far had either no instruction file or a tracker without a deployment.

- **Two rules in update contradict each other (finding 12, confirmed).** Step 1 puts the block "into an uncommitted instruction file listed in `.git/info/exclude`" where committed files become public. Step 3 says "inside the project's existing instruction file … never a second file beside it". With an already committed `CLAUDE.md` in a public repository, the two cannot both be followed. This run did not exercise it, because the newcomer said "private". Neither the small-website scenario (no file) nor the fixed own-rules scenarios hit it.
- **The playbook does not read the tracker (finding 15, confirmed).** Step 2 asked "who will use it" and got "I don't know yet". The tracker held the answer: issue #3, from a colleague, asks how to run the tool on their own files, and it surfaced only in update step 5. The playbook's step-2 clause "unless … the repository already says it" does not name the tracker.
- **The first answer came late (finding 14).** "What should I do first?" got `/kaizen:update` in the fifth message, after two safety rounds, a users question and the path. The README and the playbook disagree on what comes first, and the playbook gives no count of questions ahead.
- **The owner rule blocks more than it needs to (finding 16).** With the owner unknown, M3 says "pushes to `main` wait for their answer". Every push to `main` rebuilds the site, so the rollout's own `CLAUDE.md` change is blocked too, although it does not touch `docs/`. The rule does not separate changes that reach the site from those that do not.
- **Discovery has no route without the companion (finding 17).** "I don't know" on users led to a companion that is not installed (M4), and kaizen offers nothing in its place.
- **Handling of data that may be the only copy was good.** The agent sent the tool, which writes next to its inputs, into the originals-and-copies round with no lean, and ran the tool only on copies (M2). The unanswered issue was named, with "I post nothing" (M9).

N53 therefore counts as inferred, not asked, and is weaker evidence. This matches the varied-3 note (checked: a generator flaw).
