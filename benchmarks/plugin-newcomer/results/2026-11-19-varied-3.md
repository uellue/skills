## What this combination found that the fixed scenarios could not

- **The old-block case falls through the hallway test's item 7 (checked).** The skill asks about `design/` and about committed files becoming public only "With neither standing instructions nor a ledger". An old block without a version line counts as standing instructions, so read literally the condition is false and nothing asks. The fixed existing-tool and after-merge scenarios have no old block, so they could not show this. The agent asked anyway, in M1 item 5. The newcomer's answer ("pushing main publishes docs/ as our public site") came out only because of that question. Without it the plugin would have created `design/` and the ledger in a repository that publishes on push, with nothing asking. It was harmless only because `design/` lies outside `docs/`.
- **The version line says "this project's records are older" for a project with no records (unchecked).** The project has only an old CLAUDE.md copy. The line does not say this is a first rollout, and "standing instructions" is unexplained. The fixed scenarios never show an old block together with a terse newcomer.
- **Nothing asks how a change takes effect (unchecked).** The playbook's step 1 does this, but the hallway test does not, and the agent is not told to look at `DEPLOY.md`.
- **The originals question is skipped on a judgment from the code (unchecked).** Item 3 exempts "a tool that only reads and prints", but knowing that requires reading the code, which item 2 keeps out of the brief. The logs are in git with no remote, so they may be the only copy.
- **Publicness is asked twice (unchecked).** Item 7 asks it in M1; the ledger template asks it again in M3 (item 13). A terse newcomer answers two similar questions.
- **Footprint for a read-only 30-line tool (unchecked).** Four messages, 15 items and a branch before the start, for a newcomer who says "you decide".
